# Generic constrained-device protocol

`robot_lipsync.backends.encode_json_event()` produces one compact JSON object per line for logging and bring-up:

```json
{"v":1,"sid":"turn-1","t":42,"d":96,"p":"PRESS","a":[0.01,0.0,0.43,0.18,1.0,0.0,0.0,0.0]}
```

The articulation array order is:

```text
jaw_open, lip_separation, mouth_width, lip_round,
lip_press, lip_protrusion, lower_lip_tuck, asymmetry
```

The reference ESP32 firmware uses a bounded integer command form generated by `robot_lipsync.backends.serial_v1`:

```text
LIP/HELLO
LIP/RESET <session>
LIP/EVENT <session> <relative-ms> <duration-ms> <8 channels> <intensity>
LIP/START <session> <delay-ms> <already-played-offset-ms>
LIP/COUNT <session>
LIP/END <session>
LIP/DIAG
```

All values except asymmetry are integers from 0–1000. Asymmetry is −1000–1000. Queue capacity and session identity are checked by the device. Replies are `LIP/OK`, `LIP/ERR`, or `LIP/EVENT`, so unrelated audio and servo replies on a shared serial stream are ignored safely. The board emits `LIP/EVENT VISIBLE_START` with its monotonic millisecond clock when it renders the first active event.

JSONL remains useful as a human-readable transport, but the bounded integer protocol avoids a JSON parser and dynamic allocation on the MCU.
