# 读整本书：设计调研（草案）

> 状态：调研草案，2026-10-09，尚未实现。承接 [需求文档](../requirements.zh-CN.md) 4.4 节 R4.5–R4.8（在读与暂停）。

## 1. 现在卡在哪

- `margin/ingest.py` 只认网页、PDF、txt/md/html，超过 12000 词直接截断（`MAX_WORDS`）。一本书通常 8 万到 20 万字，会被砍掉大半。
- `brain.build_lesson` 把整篇文章一次交给模型，排出讲解步骤。整本书放不进一次请求，也不该一次讲完。
- 每次阅读是一个独立文件夹（`readings/`），没有"这是哪本书的第几章""上次读到哪"的记录。

所以要加的是一层"书"：书拆成章，记住进度，每晚从书里切一段，交给现有的讲读流程。讲读、划线、笔记、嘴型、复习题、读书报告都沿用，不重写。

## 2. 三种读法

先按书的类型给默认读法，读者随时可以换。

| 读法 | 适合 | 读者想要的 | 图书管理员做什么 |
|---|---|---|---|
| **拆书** | 社科、知识类、非虚构 | 知道这本书讲了什么、哪些观点重要 | 先给全书地图，再按主题逐章讲；不要求读原文 |
| **精华原文** | 同上，但想见到作者原话 | 不读全文，只读最值得读的几段 | 从书里挑原文段落，和你一起逐句读，段与段之间由它讲上下文 |
| **读原文** | 小说、散文 | 读文字本身 | 尽量不打扰；读前给不剧透的前情提要，读中只在你问或真有难点时开口 |

### 2.1 拆书（参考 Adler《如何阅读一本书》的"检视阅读"和"分析阅读"）

- **第一晚：全书地图。** 这是什么书、想回答什么问题、分几部分、每部分的核心主张。读者可以在这一晚决定：整本拆完，还是只挑几章。
- **之后每晚一个主题或一章。** 讲论点、证据和例子，标出作者自己最看重的结论。
- **读完一部分做一次小结**，把前面几晚串起来；复习题考的是"作者怎么论证的"，不是背细节。

### 2.2 精华原文

- 每晚 3–6 段原文，按这些标准挑：作者的核心论断、关键定义、最有分量的证据或数据、论证的转折点、写得特别好的句子。
- 这几段就是现有课程格式里的 `paragraphs`，讲解照常逐句聚焦、划线、加笔记；段与段之间插一句"中间作者讲了什么"。
- **原文必须逐字核对**：模型挑出的每一段都要在书的原文里找到完全一致的文字，找不到就丢掉重挑。不能出现编出来的"原文"。

### 2.3 读原文（小说、散文）

- **读前**：上次读到哪，一两句话的前情提要，必要时附"目前出场的人物"。
- **读中**：默认安静。文字照常显示，可以选择让声音朗读（嘴型照常）。你可以随时问：这个词什么意思、这人是谁、这个典故出自哪。只有真正的难点（典故、旧词、方言、外文）才主动加一条笔记。
- **读后**：不出考试题。问一两个开放的问题（你注意到了什么、怎么看某个人物），把你划的句子收进这本书的摘抄。
- **不剧透**：模型能看到的只有你已读到的位置之前的原文和摘要。问到后面的情节，它会说"还没读到"。这一点 Kindle 的 Ask this Book 和 Recaps 都在做，开源项目里大多还没做到（见第 4 节）。

### 2.4 每晚读多少

按读者设定的阅读时间换算。粗略估计：中文默读每分钟 300–500 字，听讲解会慢一半。读原文一晚大约 5000–10000 字，拆书一晚一章或一个主题。切分只在章节、小节或段落边界切，不切在句子中间。

## 3. 数据怎么存

```
~/Bibliothecary/books/<书名>/
  book.json        书目信息、读法、章节列表、进度（当前位置、读到最远的位置）
  chapters/NN.txt  每章原文（只存在本地）
  map.json         每章摘要、人物/术语、候选原文段落；整本书的地图
  excerpts.md      你的摘抄
```

- 每晚的阅读仍是 `readings/` 下的一个文件夹，多记两个字段：`book`（哪本书）、`range`（第几章第几段到第几段）。现有的读书报告、问答记录不用改。
- 进度分"当前位置"和"读到最远"两个：往回翻不影响剧透边界。
- 第二天接着读时，用上一晚读书报告里"还没弄懂的地方"和章节摘要生成开场的回顾，对应需求 R4.5。

### 3.1 章节摘要怎么做

BooookScore（ICLR 2024）比较了两种整本书摘要的做法：**逐章增量更新**细节更多但连贯性较低，**分层合并**更连贯但细节少。我们两种都用，按读法分：

- **小说、散文用增量**：读到第 N 章时，只用第 1 到 N 章生成"到目前为止"的摘要。天然不剧透。
- **非虚构用分层**：章 → 部分 → 全书，正好就是拆书第一晚要的全书地图。
- 摘要在导入时一次做好、存起来，之后每晚只读不重算，省钱也稳定。

整本书范围的提问（"作者前面在哪说过这个"）先用章节摘要找到可能的章，再把那几章原文交给模型。这是 RAPTOR 那种"摘要树"的简化版，先不引入向量数据库；书多了、问题多了再加。

## 4. 现成的开源项目，能不能直接并进来

本项目是 MIT 协议，并进来的代码必须协议兼容。

| 项目 | 协议 | 做了什么 | 结论 |
|---|---|---|---|
| [karpathy/reader3](https://github.com/karpathy/reader3) | MIT | EPUB 按目录拆章，一次显示一章，方便把章节交给模型 | 参考它的章节/目录数据结构。它依赖 EbookLib（AGPL），所以解析部分自己写：EPUB 本身是 zip 包，读 OPF 和目录文件即可 |
| [lilakk/BooookScore](https://github.com/lilakk/BooookScore) | MIT | 整本书摘要的两种做法和评测 | 借用增量/分层两种提示方法（见 3.1），不整个并入（它主要是评测工具） |
| [parthsarthi03/raptor](https://github.com/parthsarthi03/raptor) | MIT | 把长文本建成摘要树，用于整本书问答 | 第二阶段再考虑；先用章节摘要的简化版 |
| [booknlp/booknlp](https://github.com/booknlp/booknlp) | MIT | 小说人物识别、指代消解、对话说话人 | 只支持英文，要装 PyTorch，太重；中文小说用模型直接列人物。以后英文小说可选 |
| [shutootaki/bookwith](https://github.com/shutootaki/bookwith) | AGPL-3.0 | EPUB 阅读器加 AI 伴读、三层记忆 | 协议不兼容，不能并入；作者自己说还没做防剧透 |
| [raahelpie/lumen](https://github.com/raahelpie/lumen)（Marginalia） | 未写明 | EPUB 伴读，把当前章节和阅读进度交给模型来防剧透 | 没有协议，不能拿代码；思路和我们一致 |
| [EbookLib](https://pypi.org/project/EbookLib/) | AGPL | Python 读写 EPUB | 不用，原因同上 |
| calibre 的 `ebook-convert` | GPL | MOBI/AZW3 转 EPUB | 不并入代码；电脑上装了 calibre 就调用它的命令行，没装就只支持 EPUB/TXT/PDF |

结论：**没有一个能整体并入的现成项目**。能直接用的是思路和 MIT 代码片段：reader3 的章节结构、BooookScore 的两种摘要方法。真正要我们自己写的是"进度 + 不剧透 + 三种读法"，这正好也是现有项目都没做好的部分。

## 5. 书从哪来

- 读者自己的文件：EPUB、TXT（中文小说常见，按"第 X 章/回"切章）、PDF（有书签就按书签切）。在 Telegram 里直接把文件发给图书管理员。
- 公版书：Standard Ebooks、Project Gutenberg、维基文库（需求文档 4.2 已列）。
- 有 DRM 的商店电子书（Kindle 商店、微信读书等）读不到，也不去破解；Kindle 上只能用我们的网页阅读页。
- 书的原文只存在本地，只把当晚需要的那一段发给模型。

## 6. 分几步做

1. **读原文 + 进度**（最小可用）：导入 EPUB/TXT，切章，记进度，每晚切一段，读前不剧透的前情提要，Telegram 收文件。
2. **拆书 + 精华原文**：导入时生成章节摘要和全书地图；原文逐字核对。
3. **整本书提问、人物表、摘抄本**；书多了以后再考虑向量检索。
