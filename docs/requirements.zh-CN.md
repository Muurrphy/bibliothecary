# Bibliothecary（图书管理员）需求文档

> 状态：草案 v0.2，2026-10-08。v0.3（读书报告归档、三段式讲读）和改名已实现，其余尚未实现。
> [English](requirements.md)

## 0. 一句话

**Bibliothecary 是一个私人图书管理员**：白天在聊天框里和你商量今晚读什么，傍晚备好导读和笔记，睡前在 Kindle 或手机上给你讲，讲完把这一晚的问答整理成读书报告存档，并据此安排下一次的书。

它不只是一个"读完就结束"的阅读工具，而是一条闭环：

```
书库 → 商量选书 → 备课（导读、笔记）→ 睡前讲读 → 读书报告归档 → 更新你的知识地图 → 下一次选书
```

## 1. 名字和组成

| 名字 | 是什么 |
|---|---|
| **Bibliothecary**（中文：**图书管理员**） | 整个项目。英语里"图书管理员"的旧词，1610 年代进入英语，来自拉丁文 *bibliothecarius*。 |
| 命令 | `bibliothecary`，短命令 `biblio` |
| **Margin**（页边） | 阅览室：现有的 Kindle 阅读页、讲稿、打断提问。保留原名，作为组件。 |
| **robot_lipsync**（嘴） | 会说话的嘴：手机、iPad 或 OLED 上的口型。保留，作为可选组件。 |

## 2. 设计依据：图书管理员的职责

我们不是从"AI 能做什么"出发，而是从"一个好的图书管理员应该做什么"出发，把每一项职责对应到一项功能。

| 图书管理员的职责 | 对应到我们的功能 |
|---|---|
| **馆藏建设**：决定收什么、从哪收 | 书库：一份有品味的官方来源清单，分论文、新闻与长报道、书、散文；只收经典，或又新又好的 |
| **参考咨询**：先弄清读者真正想知道什么 | 每天在聊天框里主动问你一次今晚想读什么；第一次使用时了解你的兴趣和目标 |
| **读者顾问**：按人推荐，经典和新作搭配 | 选书规则：经典与新作交替、难易交替、按月节奏排布，不会天天塞论文 |
| **编目**：每本书都有记录、能查到 | 每篇文章入库时编目：来源、类型、主题、难度、是否读过，避免重复推荐 |
| **借阅记录** | 每晚的问答完整存档，写成当天的读书报告 |
| **读者教育**：教人读懂、会读 | 讲读有结构：先补先验知识，再讲正文，最后复习并提问 |
| **了解读者的知识水平** | 知识地图：从白天聊天和过往读书报告里判断你哪里懂、哪里有空缺 |
| **为读者保密** | 真正的图书管理员不会泄露借阅记录，所以只存在本地 |

### 古今图书管理员的职责有什么不同

- **古代和早期近代**（亚历山大图书馆、中世纪修道院、17 世纪牛津博德利图书馆的 *bibliothecary*）：核心是**保管、收集、编目**。书稀少昂贵，馆员的首要义务是别让书丢、别让书坏，有时书还用链子锁在书架上。亚历山大的卡利马科斯编了《皮纳克斯》，被认为是最早的书目之一；1627 年诺代（Gabriel Naudé）写《关于建立图书馆的建议》，主张既收古典名著也收新作，这正是我们"经典与新作"规则的老祖宗。
- **现代**（19 世纪末以后）：重心从"守书"转向"服务读者"。出现了参考咨询、读者顾问、读者教育；为读者保密成为美国图书馆协会伦理准则的明文条款（1939 年起）。
- **我们取两者之长**：从古代取"认真编目、有品味地收书"，从现代取"围着一个具体的人服务、保护他的隐私"。

> 以上历史细节凭已有知识写成，对外发布前需要核对出处。

## 3. 怎么和图书管理员说话：三个入口

用户不一定有自己的 personal agent，所以要有多个入口，**背后是同一个图书管理员、同一个书库**。

| 入口 | 适合谁 | 优先级 |
|---|---|---|
| **Telegram 机器人** | 没有 personal agent 的人。图书管理员就住在一个聊天框里：它主动来问你，你也可以随手丢链接、聊想法 | P0（第一版） |
| **MCP 接口** | 有 personal agent 的人（Claude、ChatGPT、OpenClaw 等）。把书库、读书报告、选书工具暴露给你的 agent，由它来和你沟通 | P0 |
| **本地网页** | 在电脑上浏览书库、读书报告，手动调整计划。现有的 `/remote` 页面可以扩展 | P1 |
| WhatsApp、微信、邮件 | 以后再说。WhatsApp 要走 Business API，需要申请且可能收费；微信个人号没有正式接口 | P2 |

需求：

- R3.1 三个入口共用一套后端和数据，任何入口说的话都进同一份记录。
- R3.2 Telegram 机器人只回应绑定的那一个用户，其他人发消息一律不理。
- R3.3 MCP 至少提供这些工具：查书库、加入书库、看今晚的安排、改今晚的安排、读某天的读书报告、搜过往读书报告、查知识地图。
- R3.4 主动提醒需要电脑（或家里的小服务器）开着。文档要写清楚，并提供"开机自启"的做法。

## 4. 书库（馆藏建设与编目）

### 4.1 原则

- 先做**通用框架**，每个人可以改自己的书库；默认书库要**有品味**：要么是经典，要么又新又好。
- 默认来源写成一份可编辑的清单文件（YAML），社区可以提 PR 补充。每个来源注明：类型、语言、是否免费、许可、可信等级。
- 优先选择**免费、合法可读**的来源。付费墙内容只记链接和元数据，由用户自己打开。

### 4.2 默认书架（初稿，待核对）

| 书架 | 默认来源 | 怎么判断"经典"和"新而好" |
|---|---|---|
| **论文** | arXiv（新）、OpenAlex 和 Semantic Scholar（元数据和引用数）、PubMed（生物医学）、Nature / Science / Cell / PNAS 的目录 RSS、Annual Reviews（综述） | 经典：领域内高被引且发表超过 10 年。新作：近 6 个月、顶刊或高关注度、与你的兴趣相关 |
| **新闻与长报道** | AP、Reuters（事实）；Quanta Magazine、Knowable Magazine、Aeon、ProPublica（深度、免费）；中文科学媒体如《知识分子》《返朴》 | 不追热点快讯，选能读 20 分钟以上、一年后仍值得读的长文 |
| **书** | Standard Ebooks（精校公版书）、Project Gutenberg、Open Library（元数据）、维基文库、中国哲学书电子化计划；用户自己的 EPUB 或 Calibre 书库 | 经典书目清单加用户自己的书；一本书按章节拆成多晚读 |
| **散文** | 公版散文（蒙田、兰姆、鲁迅等）、Aeon Essays | 按作者和主题策展 |
| **你自己丢进来的** | 任意链接、文件；可选从 Wallabag、Readeck 同步 | 由你决定，图书管理员只负责编目和排期 |

### 4.3 编目

- R4.1 每篇入库条目记录：标题、作者、来源、类型、语言、长度（预计朗读分钟数）、主题标签、难度、经典或新作、入库时间、状态（待读、在读、已读、暂停）。
- R4.2 去重：同一篇文章的不同链接（arXiv 和期刊版、转载）识别为同一条。
- R4.3 读过的不再推荐，除非你要求重读或到了复习时间。
- R4.4 不按语言分书架。语言只是编目里的一个字段；想只读某种语言的用户可以自己加筛选。

### 4.4 在读与暂停

一本书往往要读很多晚，中途换别的是常事。图书管理员要像真的图书管理员记得"你那本书还没还"一样，记住每本没读完的书。

- R4.5 进度自动保留：读到哪一章、哪一段，以及已经讲过的内容和问答，都记在这本书的条目里。下次接着读时，先用一两句话回顾上次讲到哪。
- R4.6 每天检查一次在读的书。看到合适的时机就提一句，例如：
  - 某本书已经停了一周以上；
  - 你今天说的话正好和那本书有关；
  - 本周节奏里正好空出"书"的那一晚。
  提醒要克制：同一本书一周最多提一次，你说"不了"就隔更久再提。
- R4.7 你明确说不想读了，这本书就移到**暂停书架**：在书库里置灰显示，不再主动提醒，但进度和记录都保留。你随时可以把它拿回来。
- R4.8 暂停书架上的书，图书管理员几个月后可以问一次"还想读吗"，你说不想就不再问。

## 5. 选书与排期（读者顾问）

### 5.1 每天的流程

| 时间（默认，可改） | 发生什么 |
|---|---|
| 白天某个时刻，每天一次 | 图书管理员在聊天框里主动问你：今晚想读什么？并给出 2–3 个建议，各附一句理由 |
| 白天 | 你可以回答、改主意、丢链接、随便聊；它顺便了解你对相关概念熟不熟 |
| 傍晚截止时间（如 19:00） | 敲定今晚篇目。没回复就按计划自动选一篇，照常备课、照常讲读 |
| 睡前之前 | 备好"导读与笔记"并发到聊天框；同时生成阅览室要用的讲稿 |
| 睡前 | 在 Kindle、手机或 iPad 上讲读（见第 6 节） |
| 讲完后 | 自动生成当晚读书报告并归档 |

默认是睡前读书，用户可以改成早上或任何时间。

### 5.2 月度节奏（默认模板，可改）

- 每周 1 篇论文，经典和新作隔周交替
- 每周 2–3 篇长报道
- 一本书分章节，大约一个月读完
- 每周一篇散文
- 每周留一晚"复习夜"：不读新东西，回顾本周的问题
- 在读的书优先接着读，不另起新书（见 4.4）
- 每月最后一天出月报：读了什么、问题集中在哪、知识地图的变化、下月建议

需求：

- R5.1 节奏模板是配置文件，可以改。
- R5.2 选书时同时考虑：节奏模板、你今天说的话、知识地图（补空缺还是顺着兴趣走）、去重。
- R5.3 每个推荐都要能说出理由（"你上周问过两次 X，这篇正好讲 X"）。
- R5.4 你可以说"不想读这个""这个太难"，这些反馈也要记下来。

## 6. 睡前讲读的结构（读者教育）

讲读分三段，对应读书报告的结构：

1. **预习：先验知识**。读这篇之前你可能不知道的概念、背景、术语。按知识地图挑选：你已经懂的就跳过，不懂的先讲。
2. **正读**。就是现在 Margin 的讲稿：这篇讲什么、背景、主要观点、为什么重要，可以随时打断提问。
3. **复习：提问**。讲完后问你 2–3 个问题，听你回答，给出反馈。然后结束。

需求：

- R6.1 预习部分的长度可以调，也可以跳过。
- R6.2 复习提问可以用语音回答，也可以在聊天框里第二天补答。
- R6.3 回答得好、不好、跳过，都写进读书报告和知识地图。

## 7. 读书报告（借阅记录）

### 7.1 每晚一份

存成 Markdown 文件，带 YAML 元数据头，人能读，agent 也能读。

```markdown
---
date: 2026-10-08
title: 章鱼怎么睡觉
source: https://...
shelf: 长报道
kind: 新作
minutes: 22
concepts: [REM 睡眠, 头足类, 色素细胞]
mood: 有点累，提前结束了复习
---

# 2026-10-08 · 章鱼怎么睡觉

## 为什么选这篇
## 导读：读之前要知道的
## 要点笔记
## 我问了什么、它怎么答（逐条原文）
## 复习提问和我的回答
## 我还没弄懂的
## 值得追的线索（可能成为以后的书）
## 和以前读过的哪些有关
```

### 7.2 汇总

- 每周、每月汇总报告（月报见 5.2）。
- 读书报告目录本身就是一个可以用 git 管理的文件夹，也可以放进 Obsidian 之类的笔记软件。

需求：

- R7.1 问答原文完整保存，不做有损摘要；摘要和原文分开放。
- R7.2 导读和笔记在讲读之前就生成（作为第 5 节"睡前之前"那一步），讲完后补上问答和复习部分。
- R7.3 读书报告可以通过 MCP 读取和搜索；只读接口默认开启，写入需要用户同意。
- R7.4 读书报告用讲解语言写：用户让它用什么语言讲，报告就用什么语言。文章原文的引用保留原文。

## 8. 知识地图（了解读者）

图书管理员怎么知道你懂不懂某个东西？

- **来源一：白天聊天**。商量选书时顺便问一两句，或从你说的话里看出来。
- **来源二：过往读书报告**。你问过什么、哪里答不上来、哪些概念讲过几次。
- **来源三：复习提问的结果**。

需求：

- R8.1 每个概念记录：第一次出现在哪篇、讲过几次、你问过几次、复习答得怎样、最近一次接触时间、当前判断（懂、半懂、不懂）。
- R8.2 预习时据此决定讲哪些先验知识。
- R8.3 复习排期借用间隔重复算法（如开源的 FSRS），让旧问题在合适的时候回来。
- R8.4 知识地图是一个你能看懂、能手动修改的文件。图书管理员判断错了，你可以纠正。

## 9. 设备组合：怎么用都可以

| 组合 | 体验 |
|---|---|
| 只用手机 | 手机上看文章、听讲解、说话提问，可选显示嘴 |
| Kindle + 电脑 | 现在的基础用法：Kindle 显示，电脑控制 |
| Kindle + 手机 | Kindle 显示文章，手机出声、听你说话、显示嘴 |
| 手机 + iPad | 一个看文章，一个当嘴 |
| 以上任意 + 更多屏幕 | 额外的嘴同步说话 |
| 只用聊天框 | 不讲读，只在 Telegram 里收导读、读书报告，聊天讨论 |

需求：

- R9.1 每种组合都有一条命令或一个二维码就能开始。
- R9.2 嘴型（robot_lipsync）始终是可选的，不装也能用。
- R9.3 目前任何组合都需要一台电脑或家庭服务器在后台跑。文档要说清楚。

## 10. 隐私（为读者保密）

真正的图书管理员不会泄露借阅记录，所以只存在本地。

- R10.1 书库、读书报告、知识地图、聊天记录全部存在本地文件夹。
- R10.2 调用大模型和语音服务时，只发送当次需要的内容，不上传整个记录库。文档列明每个外部服务会收到什么。
- R10.3 支持完全本地的模型（如 Ollama）作为选项，代价是效果可能差一些。
- R10.4 Telegram 的消息会经过 Telegram 服务器，这一点要明确告诉用户；在意的人可以只用本地网页或 MCP。
- R10.5 一条命令导出全部数据，一条命令删除全部数据。

## 11. 借用别人的东西

| 部分 | 借谁的 | 方式 |
|---|---|---|
| 论文元数据和引用数 | OpenAlex、Semantic Scholar、arXiv API | 直接调用公开接口 |
| 按阅读记录给新论文打分 | zotero-arxiv-daily 的思路 | 借思路，自己实现 |
| 复习排期 | FSRS 算法（开源） | 作为依赖库 |
| 收藏同步 | Wallabag、Readeck 的 API | 可选插件，只调接口不拷代码 |
| Telegram 机器人 | python-telegram-bot 等成熟库 | 作为依赖库 |
| MCP 接口 | 官方 MCP Python SDK | 作为依赖库 |
| 记忆和报告存成 Markdown 加 git | The Librarian 的格式思路 | 借思路 |

要求：每个依赖在 `docs/third-party.md` 里写明许可证；不把 AGPL 等传染性许可的代码复制进本仓库，只通过接口调用。

## 13. 已定的决定

| 问题 | 决定 |
|---|---|
| 命令名 | 同时提供完整命令 `bibliothecary` 和短命令 `biblio` |
| 傍晚截止前没回复 | 按计划自动选一篇，照常备课、照常讲读 |
| 一本书读到一半想换 | 见 4.4：进度自动保留，图书管理员找合适的时机提醒；真的不想读，就放到"暂停书架"置灰 |
| 默认书库分不分语言 | 不分。语言只是编目字段（R4.4），想按语言筛选的用户自己设置 |
| 读书报告用什么语言 | 跟讲解语言走（R7.4） |
