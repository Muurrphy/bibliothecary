# 0.5.0a1：长期使用预览与验收

基线为完整 0.4.0（`85529e1`）。这是待实机验收的预览版本，尚未声称完成七天使用验收。

## 产品边界

保留原来的黑白杂志式界面与嘴型布局。AI 承担记录、整理、检索、安排的工作；新增功能不等于增加阅读器按钮。通过 Telegram 商量，手机／Kindle 在家中阅读。模型和语音供应商保持原有配置。

记录不要求读者说“记住”。每条收到的文字、每条获得的语音转写都会先保存，包括闲聊、个人经历、反对意见、被打断和未获回答的发言。默认不保存麦克风录音原件。无法取得转写时明确记缺口；不能声称程序能恢复没被麦克风收到或没转写出来的话。

## 每次阅读的两份记录

- `transcript.md`：完整逐条文字原文，区分读者和 AI，带时间、原文位置、转写及播放状态。语音转写标为未经人工核准；不由模型润色或覆盖。
- `notes.md`：整理层，区分读者疑问、观点、个人联想与经历、延伸话题、阅读感受，以及 AI 的问题、解释与建议。每条链接回原话，并保留对应全文。一个发言可以属于多个类别。分类失败或遗漏保留为待整理。
- `report.md`：原有读书报告加上这两份内容，作为可以独立阅读的完整交付文件。
- SQLite、`session.jsonl`：原始事件与来源。整理结果不替代证据；“已回答”和“已掌握”不是一回事。

断网或模型失败时，原话和未分类笔记仍会生成。可以用现有 `biblio report` 重新整理；启动 Telegram 时会恢复上次中断的整理任务。程序不会把书内指令当作读者请求来修改笔记或偏好。

## 已实现的工程范围

1. 阅读交接和迟到语音隔离、位置／问答恢复、原文手动推进及明确结束、旧书籍对象字段合并、损坏摘要隔离、原始记录优先归档、防剧透上下文裁剪。
2. SQLite WAL 数据底座、旧 JSON/JSONL 迁移及备份、来源明确的记忆与纠正／忘记、完整历史词项检索（支持中文）、URL/DOI/内容去重、筛选和拒绝反馈、全文可读状态、正文与检索缓存。
3. 目标、路径字段、每周阅读节奏、最多两题的日复习入口、明确自评及 1/3/7/14 天间隔、带证据的周回顾。没有把模型评分当作理解事实。
4. 可恢复后台任务、取消及显式重试、时区、健康检查、可选 macOS 登录启动；启动脚本不安装或升级依赖。

阅读显示调整仍可用话语提出。明确保存命令只用于强调或单独摘录，绝不是保存评论的前提。自然语言动作目前覆盖常用表达，不能声称任意措辞都能可靠触发动作。

## 迁移、启动和回滚

先退出旧程序，再在单一版本上操作同一馆藏。保留现有 `.env`，不要把密钥复制进仓库。

```sh
python3 -m venv .venv
.venv/bin/pip install -e '.[dev]'
.venv/bin/biblio migrate
.venv/bin/biblio health
.venv/bin/biblio export /path/outside-library/backup-new-directory
sh scripts/start-librarian.sh
```

首次迁移前，旧资料复制至馆藏 `backups/before-sqlite-*`，带原文件 SHA256 清单；旧文件保留。SQLite 是迁移后的主记录，JSON/JSONL 是兼容导出，不能同时运行旧版程序修改导出文件。

```sh
# 在新目录恢复，绝不覆盖现有资料
biblio restore /path/to/backup /path/to/new-library
BIBLIOTHECARY_HOME=/path/to/new-library biblio health
```

macOS 可选：`biblio service write --launcher /absolute/path/to/launcher.sh` 只写启动配置；`enable` 才启用；`disable` 停止并保留 `.disabled` 配置。选择已经正确加载原有凭据的启动脚本。默认不会替用户启用自启动。

原始音频不加入阅读档案。原项目用于演示录屏的 `MARGIN_RECORD_DIR` 是另一项显式配置，勿把它与对话归档混淆。

## 2026-10-09：真实试用后的第二轮修复

这次真实反馈暴露了离线成功未覆盖的产品问题：问答提示词强制简答并回到旧稿；
语音不能执行跨材料准备；告别被打断会越过结束记录；对非本人的讲话仍继续响应。

- 阅读模型现在可提交经过验证的 librarian 动作，经典与实时路径共用执行器。
  原文引用来自实际 sentence；换作品使用后台检索、提取正文、检查是否符合请求，
  再打开新阅读。原文读法直接读已提取文字，不把模型生成内容冒充作品。
  保存跨篇来路和原位置；迟到结果经请求编号与阅读 generation 检查，不能抢走新阅读。
- 讨论可以留在问题上，允许具体延伸和一次自然追问。人物信仰等事实必须核验；
  不以文学主题推断个人宗教立场。页面、模型与语音供应商未改变。
- 中途暂停保留完整转写，明确结束或 90 秒对话静默触发归档；告别不再控制归档。
  静默不是完成整篇。后续对话结束后发送更新报告，后台总结不阻塞本地暂停。
- 明确说“不是在和你说话／先不用管我”后保持安静，直到“回来吧／继续”；
  已接收到的转写仍按原文保留。
- 整理后分析读者证据：有限的交互策略（先原文、延伸、对话、详略）与暂定兴趣分开，
  保留源话链接、时间和记忆编号，/profile 可纠正或忘记；忘记后不参与交互指导。
  每天后台检查新笔记，最多准备一份可选延伸，不自动切换正在读的篇目。
  这是有出处的交互策略调整，不是模型自行改代码或修改可执行 skill。

新增回归覆盖工具传递与执行、跨篇返回、迟到结果、原文验证、暂停／告别／静默归档、
更新报告、后台整理不阻塞、证据校验、遗忘传播、保持安静。
真实模型挑选正文的准确率、打开速度、追问是否自然，仍需下一轮实机反馈；
联网和备课不能保证瞬间完成，失败必须保留原位置并说明没有取得正文。

实现参考：[OpenAI Realtime conversations](https://developers.openai.com/api/docs/guides/realtime-conversations)。
沿用现有 JSON 步骤传输与应用执行器；没有替换用户的实时语音服务或引入新提供商。

检索补充：按 [OpenAI Web search 文档](https://developers.openai.com/api/docs/guides/tools-web-search)
显式要求执行搜索，同时读取完整来源列表，避免“允许搜索但实际凭记忆回答”以及只保留引用链接。
可选延伸最多尝试两个有出处的兴趣方向、每天最多准备一份；没有合格正文时记录失败原因。
