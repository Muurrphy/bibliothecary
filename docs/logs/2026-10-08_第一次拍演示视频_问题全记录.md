# 2026-10-08 第一次拍演示视频：问题全记录

这一晚第一次用 Telegram 图书管理员 + 手机讲读页，完整拍一段演示视频。下面按出现的先后，把遇到的每个问题都记下来：当时看到了什么、原因是什么、怎么修的（提交号）、现在的状态。最后一节是还没解决的问题和给以后的提醒。

> 环境：Mac 上运行 `zsh ~/Desktop/启动\ Bibliothecary\ 电报.command`（`biblio telegram --explain "Simplified Chinese"`，同时开着阅览室）；手机打开 `/phone` 讲读页；iPhone 自带录屏。
> 当晚 `.env`（不上传 GitHub）：`MARGIN_MODEL=gpt-4.1-mini`，`BIBLIOTHECARY_CHAT_MODEL=gpt-5.6-sol`，`MARGIN_SEARCH_MODEL=gpt-5.6-terra`，ElevenLabs 音色 Evil AI（eleven_v4，钥匙串 “Lilyput ElevenLabs API Key”），`MARGIN_VOICE_CACHE_DIR`、`MARGIN_RECORD_DIR` 指向 `~/Bibliothecary/`。

## 一、Telegram 里聊天、找文章

### 1. 推荐的东西全是垃圾，说话干巴巴
- **现象**：问“今晚读什么”，推荐《黑神话：悟空》、一堆研究短剧的论文；不问你想要什么，说话很干。
- **原因**：OpenAlex 按关键词搜，噪声很大（“适合拍 demo” 搜出政治哲学里讲 demos 的论文）；提示词逼它像发短信一样简短；当时为了绕开空回复，聊天用的是较弱的 gpt-4.1-mini。
- **修法**：云端把图书管理员改成“参考咨询台”（db29c21）：先问清楚、再搜、每批结果再严格筛一遍；聊天可以单独用更强的模型。`.env` 加 `BIBLIOTHECARY_CHAT_MODEL=gpt-5.6-sol`（当时账号里最强的、能用 chat 接口的 gpt-5 系列；gpt-5.5-pro 不支持该接口）。
- **状态**：已修。

### 2. 新浪财经那篇文章一直“阴魂不散”
- **现象**：不管怎么改，聊天里总提新浪财经那篇诺奖新闻。
- **原因**：它被准备成了一篇读物，存在 `~/Bibliothecary/readings/`，每次聊天都会作为“读过的东西”带进上下文。
- **修法**：清空记忆。聊天记录 `chat.jsonl`、读者画像 `reader.json`、读物文件夹都**挪进备份**（`~/Bibliothecary/_旧记忆备份_2026-10-08*`），配对信息 `telegram.json` 保留。这一晚一共清了五次。
- **状态**：处理完毕；做法记在这里，以后照做。

### 3. 不承认今年的诺奖，把得主的论文全扔掉
- **现象**：问今年医学奖得主的论文，它说“查不到 2026 年得主”，让你把名字发给它。
- **原因**：今年的奖比模型训练的知识新，诺奖官网又还没被搜索收录；负责筛选的那一步也不知道今年谁得奖，把得主的论文当成不相关全扔了。另外，当时网页搜索用的是 gpt-4.1-mini，引用的链接很少。
- **修法**：ad8c0a8：新增“查事实”（不限网站的网页搜索），遇到最近的事先查清谁得了奖、为什么，再按名字找论文；搜索返回的文字同时交给聊天和筛选两步；链接里的 `utm_source=openai` 尾巴去掉。`.env` 加 `MARGIN_SEARCH_MODEL=gpt-5.6-terra`（sol 搜一次要将近两分钟，terra 约 20 秒）。
- **状态**：已修。实测能答出 Deisseroth、Hegemann、Nagel 和光遗传学。

### 4. 推荐付费墙文章，还没等你选就开始准备，报错是英文
- **现象**：推荐 Nature 论文，同一条回复里就开始“备课”，接着甩出一句英文 `found almost no text`。
- **原因**：筛选只看标题，不看能不能读全文；“准备”可以在第一次推荐时就触发；报错直接把英文异常发了出来。
- **修法**：18eda17：推荐前逐个打开链接，确认整篇读得到（只有摘要或被付费墙挡住的不推荐）；只有读者选了之前推荐过的那篇（或自己给的链接）才准备；付费墙失败改成中文说明。顺手关掉 pypdf 刷屏的字体警告。
- **状态**：已修。
- **教训**：这一晚有两条回复是 Claude 在自己的环境里替机器人生成后发出的。Nature 那篇在那边打得开，在你的 Mac 上却被付费墙挡住，于是推荐了一篇你读不了的。**以后不要在别的机器上替机器人生成回复。**

### 5. OpenAI 余额用完，机器人只说“连不上模型”
- **现象**：录到一半，机器人回“我这边连不上模型，稍后再说”。
- **原因**：OpenAI 账户余额用完（`insufficient_quota` / `credit_balance_exhausted`），所有模型都返回 429。用最贵的 gpt-5.6-sol 聊天、每次搜好几轮，花得很快。
- **修法**：你充了值。0910a42：余额用完、密钥不对，都会在聊天里直接说清楚。
- **状态**：已修。想省钱可以把聊天模型换成 gpt-5.6-terra。

### 6. 拍摄时聊天总跑题，每次录都不一样
- **现象**：“今晚读什么”一会儿推临床应用，一会儿说自己“偏题了”，没法稳定地拍。
- **修法**：2d7ac15：剧本模式。在 `~/Bibliothecary/demo.json` 里写好每一步的回复（这一晚用的是机器人自己真实生成过、效果最好的四条），不管打什么字都按顺序回下一条；最后一步发出讲稿要点和“📖 在手机上读”按钮。`"next"` 记着走到第几步，改回 0 就能重来，不用重启；步骤用完就恢复成正常的机器人。手机讲读页那部分始终是现场的。
- **状态**：已加。文件还在，以后拍还能用。

## 二、手机讲读页

### 7. 手机没声音，嘴不动
- **现象**：上面的文字在走，下面的嘴不动，也听不到声音；它听得到你说话。
- **原因**：`biblio telegram` 开的阅览室默认是静音模式，而且什么提示都没有。听用的是 OpenAI，出声要用 ElevenLabs，两条路是分开的。
- **修法**：8c120e0：`--voice` 默认改成 `auto`，填了 ElevenLabs 密钥和 `MARGIN_ELEVEN_VOICE`（或 `ELEVENLABS_VOICE_ID`）就自动出声，没填时启动会打印 `voice: SILENT…` 说明缺什么；中英文 README 和 `.env.example` 写清楚了怎么接自己的声音（包括克隆的声音）。
- **状态**：已修。

### 8. 字幕框第三行被切掉一半
- **现象**：底部 “READING” 字幕本该显示三行，第三行被一条白边盖住一半，看着很难受。
- **原因**：字幕框高度按屏幕比例算，到手机上正好停在第三行中间。
- **修法**：39ef76c：按整行算高度，手机上固定显示完整三行，新的一句滚上来时对齐到整行。
- **状态**：已修（截图对比过）。

### 9. 复习提问时，屏幕一直停在第一题
- **现象**：声音已经问到第二题，屏幕还是第一题的问答。
- **原因**：复习题没有对应的原文句子，答完以后没人清掉上一轮问答的显示。
- **修法**：a3c1794：讲稿一往下说，就清掉上一轮问答。
- **状态**：已修。

### 10. 回答复习题时一停顿就被切断
- **现象**：答第三题答得比较长，中间换了口气，后半句“精确的研究工具”被单独当成一个问题，回答驴唇不对马嘴；正片里也有回答被打断作废的情况。
- **原因**：安静 0.7 秒就算说完。
- **修法**：ddf3cd0：回答复习题时停顿 1.6 秒内不算说完，最长可以说 30 秒；0910a42：平时提问停顿 1 秒内不算说完，最长可以说 20 秒。
- **状态**：已修。

### 11. 说了“刷新”页面就没反应；读完以后没法让它再问一遍
- **现象**：说“你卡了刷新一下页面”，它真的刷新了页面，但一句话也不说，看起来像卡死；三道复习题问完，说“重新问一遍”，它不肯。
- **原因**：“刷新”是直接执行的命令，执行后不出声；复习问完这篇就算读完，没有“再问一遍”这个命令。
- **修法**：0910a42：刷新后会说“好，页面刷新了，我们接着来”；新增“再问一遍 / 重新问我 / ask me again”，读完以后也能回到第一道复习题。
- **状态**：已修。

### 12. 读书报告写“今晚你问了 0 个问题”
- **现象**：问了很多问题，报告却说 0 个。
- **原因**：那份报告属于临时拆出来的“只有复习题”的那篇，里面没有正片里的问答；切换篇目时，前一篇还有可能漏掉问答（下一条）。
- **修法**：当晚手动合成了一份完整报告（`readings/2026-10-09-controlling-the-brain-with-light-final`，6 个问题 + 3 道复习题），23:31 由机器人发出。0910a42：没提问时不写数量。
- **状态**：已修。

### 13. 切换篇目时，报告可能漏掉前一篇的问答（偶发）
- **原因**：记录“开始”的那一条如果晚到，会把“有新内容要写进报告”的标记清掉。这也是一直时过时不过的那个测试（`test_switching_readings_files_the_last_one`）。
- **修法**：0910a42。
- **状态**：已修，全部测试连跑三遍通过。

### 14. 刷新页面不会从头讲；点 Telegram 里旧的按钮会切回旧篇目
- **现象**：以为刷新页面就能重来，结果一直从上次讲到的地方继续；点了旧消息里的“在手机上读”，又切回旧的那篇，并自动发了一份报告。
- **原因**：设计如此。刷新页面只是重画屏幕，阅览室在电脑上，讲到哪里由电脑记着；每个按钮都固定打开它那一篇；从一篇切到另一篇，会把前一篇归档。
- **当晚做法**：每重录一次就复制一份全新的读物（`…-take2/3/4`、`…-review*`），让剧本最后一步的按钮打开新的那份。
- **状态**：没改代码。应该加一个“这篇从头再来”的正式入口。

## 三、录视频

### 15. iPhone 录屏录不到手机自己发出的声音
- **现象**：开着麦克风录屏，录下来只有外部麦克风的声音，听不到它说话。
- **原因**：iOS 的限制：网页一直占着麦克风（为了能随时打断它），录屏就不录这个页面的声音。打电话、开 FaceTime 时也一样。
- **修法**：21622aa：设了 `MARGIN_RECORD_DIR` 后，手机上播的每一句都存成 mp3，并在 `timeline.jsonl` 里记下开始和结束时间；`python -m margin.stitch <文件夹>` 按真实时间把它们拼成一条音轨（被打断的句子在打断处截掉）。38e45b7：修了录音文件夹读取过早、导致没录上的问题（第一次启动时其实没在录）。aafcf25：`--start` 可以指定音轨从哪一刻开始。
- **当晚成果**：`~/Bibliothecary/录音/完整音轨_从发你好那一刻开始.m4a`，27 分 16 秒，第 0 秒对应在 Telegram 发出“你好，我叫Murphy”的那一刻（23:02:00）。
- **教训**：录制中途**不要挪动录音文件**，所有句子要留在同一条时间线上，最后只对齐一次。
- **状态**：已有替代方案，iOS 的限制本身绕不开。另一个办法是用数据线连 Mac，在 QuickTime 里录手机（声音最干净，但录不到自己说话）。

### 16. 原始音频找不回来
- **现象**：第一次录完想找它说过的音频，发现没存。
- **原因**：声音当场生成、只放在内存里，没开缓存。
- **修法**：`.env` 打开 `MARGIN_VOICE_CACHE_DIR` 和 `MARGIN_RECORD_DIR`。
- **状态**：已修。
