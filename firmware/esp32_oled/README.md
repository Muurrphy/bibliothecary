# ESP32 OLED reference firmware

This Arduino sketch shows the **Monroe lips** (梦露嘴唇): the 44 designed 128×64 one-bit frames from the Lilyput chest board (`monroe_frames.h`, generated by `tools/monroe/build_bank.py`). Like that board it shows one designed frame per event, with no cross-fades; in-betweens are separate frames, and a gap of 90 ms or less holds the previous pose instead of flashing rest. It contains no voice credentials, Wi-Fi configuration, or servo code.

Which frame: the host adds an optional 13th field, the frame index (`robot_lipsync.monroe.oled_frame`, which applies the readable English and Mandarin rules and removes flashes shorter than one 20 fps frame). Without it, `monroe_select.h` picks the nearest of the 17 muscle-target frames from the streamed channels, using the same arithmetic as the web preview (`tools/monroe/build_tables.py` writes both).

## Reference hardware

- ESP32-C3 SuperMini;
- SH1106 128×64 I2C OLED at `0x3C`;
- `SDA = GPIO6`, `SCL = GPIO7`;
- USB CDC on boot enabled;
- Adafruit GFX and Adafruit SH110X libraries.

Change [`config.h`](config.h) for another pinout. Set `ROBOT_LIPSYNC_OLED_SH1106` to `0` and install Adafruit SSD1306 to compile for SSD1306.

## Compile

```bash
arduino-cli compile --profile esp32c3 firmware/esp32_oled
```

The checked-in `sketch.yaml` pins the ESP32 core and both display libraries so local and CI builds use the same toolchain. CI compiles both SH1106 and SSD1306 variants.

Arduino IDE users should select an ESP32-C3 board and set **USB CDC On Boot = Enabled**.

After flashing, upload the no-key fixture from the host:

```bash
pip install -e ".[serial,english]"
python examples/esp32/upload_timeline.py /dev/cu.usbmodemXXXX
```

## Why this protocol is separate from generic serial traffic

Every command and reply starts with `LIP/`. Audio, servos, and the display may share one upstream link, but `LIP/ERR EVENT` can never be mistaken for an audio or motion failure.

```text
LIP/HELLO
LIP/RESET turn42
LIP/EVENT turn42 0 90 10 0 430 180 1000 0 0 0 1000
LIP/COUNT turn42
LIP/START turn42 120 0
LIP/END turn42
LIP/DIAG
```

Channel integers are the eight v1 articulation values multiplied by 1000, followed by intensity, then an optional Monroe frame index (0–43). Boards that predate the frame field read the first twelve values and ignore it. The board emits `LIP/EVENT VISIBLE_START` when the matching event is first rendered. See [`examples/esp32/PROTOCOL.md`](../../examples/esp32/PROTOCOL.md).

## Hardware truth

CI compilation proves that the sketch builds. It does not prove OLED wiring, I2C signal integrity, frame timing on long jumper wires, or visible/audio synchronization. Those require a board test and must be reported separately.
